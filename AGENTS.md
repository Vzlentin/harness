- Check: `npm run check` (Biome, oxlint, TypeScript, Vitest).
- Lint: oxlint with the anti-slop plugin, vendored in `tools/oxlint/anti-slop/` (see its `UPSTREAM.md`). Biome only formats and sorts imports. Outside data is checked with TypeBox schemas, not `typeof`.
- `docs/spec.md` is the behaviour spec: CLI commands, arguments and output lines, the tool, the host, and where state lives. Update it in the same change as the behaviour. `README.md` has only the install, a short usage and development; keep it short.
- `origin` is `Vzlentin/harness`. It continues the history of `Vzlentin/pi-subagent`, now archived, a fork of `badlogic/pi-subagent`.
- One npm package comes from this repository: `@vzlentin/harness`, with the `harness` command and the Pi extension in `pi/`. `pi/package.json` is private and is not published on its own. `setup` in `src/setup.ts` registers `pi/` with `pi install <path>` for a top-level global install. Two things run it: `scripts/postinstall.js` on a global install (npm 11; npm 12 blocks install scripts by default), which is plain JavaScript because Node does not strip types under `node_modules` and imports `dist/setup.js`; and the installed CLI, once per version (`setupOnce`). workflows calls `@vzlentin/harness/setup` too, so keep its API as `docs/spec.md` gives it. workflows takes `@vzlentin/harness` as an optional peer, so a change of the major (or of the minor before 1.0) needs a new peer range there.
- Release: a commit on `main` that changes `version` in `package.json`. `.github/workflows/publish.yml` runs the check and publishes that version to npm with trusted publishing. Do not run `npm publish` by hand.
- Dependency versions are pinned exactly. The `@earendil-works/*` packages share one version; change them together. In the root package they are plain `dependencies`.
- The root package publishes `dist/`, `pi/` and `scripts/postinstall.js`. `prepack` builds `dist/` with `tsconfig.build.json`. `dist/` is not in Git. The checkout runs from source with Node type stripping, so keep to syntax that Node can strip. `cliPath()` in `src/protocol.ts` gives the CLI that the host start and the Herdr tabs run: `dist/cli.js`, or `src/cli.ts` in a checkout.
- The host loads the `piDurable` entries of Pi's packages (such as pi-ipython) and the entries in `entries.json` (`src/entries.ts`, for packages that are not Pi packages, such as workflows).
- The files in `pi/` run inside Pi. Pi supplies `pi-ai`, `pi-coding-agent` and `pi-tui`, so they are `peerDependencies` at `"*"` in `pi/package.json`, and the extension takes them from Pi. Code that draws with Pi's components, such as `pi/chat.ts`, goes in `pi/` for this reason. From `../dist/`, it imports only `client`, `herdr`, `mirror`, `projects`, `protocol`, `tool` and `view-state`. These modules, and the modules that they import, such as `view-change`, must not import Pi packages, `chord` or `pi-durable` at runtime (types only). The type check resolves `../dist/*.js` to `dist/*.d.ts`, so `npm run check` builds `dist/` before it. Vitest resolves them to `src/*.ts`. In a checkout, the extension needs `npm run build` before Pi can load it (`pi install ./pi`).
- Tests must not call a real model, start tmux, or use the user's Pi or Git configuration. Use a temporary `PI_CODING_AGENT_DIR` and pi-ai's faux provider.
